# Ajou FoodMap API - Supabase 데이터베이스 구축

TypeScript·Express로 맛집 API를 구현하고 Supabase PostgreSQL에 데이터를 저장합니다.
서버를 완전히 종료한 뒤에도 등록한 맛집이 남아 있습니다.

## 구조

```
기존 React 클라이언트 → Express의 /api/restaurants
                      → Supabase JS SDK → Data API(HTTPS)
                      → PostgreSQL의 public.restaurants
```

| 기능 | 구현 |
|---|---|
| 맛집 목록·상세·인기 목록 | Supabase의 `restaurants` 조회 |
| 맛집 등록 | `POST /api/restaurants`로 DB에 저장, ID는 PostgreSQL IDENTITY가 생성 |
| API 경로·응답 | 기존 경로, `{ data: ... }`, camelCase 필드 유지 |
| 인기 기준 | `rating` 내림차순, 기본 최대 5개 (`?limit=N`) |
| 이미지 | DB에는 URL 문자열만 저장 |

## 기술 스택

Node.js 24.x, TypeScript, Express 5, `@supabase/supabase-js`, PostgreSQL(Supabase), dotenv.
테스트는 Jest, supertest, 로컬 PostgreSQL인 PGlite를 사용합니다.

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/health` | 서버 상태 (DB를 읽지 않음) |
| GET | `/api/restaurants` | 맛집 목록 |
| GET | `/api/restaurants/popular?limit=5` | 평점순 인기 목록 |
| GET | `/api/restaurants/:id` | 맛집 상세, 없으면 404 |
| POST | `/api/restaurants` | 맛집 등록 (`name`, `category`, `location` 필수), 성공 시 201 |
| POST | `/api/restaurants/reset-demo` | 추가한 맛집을 지우고 원본 3건으로 초기화 |
| GET | `/api/restaurants/sync-demo` | 동기 실행 비교용 |

오류 응답은 `{ "error": { "message": "..." } }` 형태입니다.

```
│   ├── routes/                    # 기존 경로

│   ├── types/                     # 응답·DB 타입

└── tests/                         # 서비스·API·SQL 검사
```

## DB 구성

`supabase/schema.sql`은 다음을 정의합니다.

- `public.restaurants` 테이블 (10개 열, `id`는 `GENERATED BY DEFAULT AS IDENTITY`)
- Row Level Security 활성화, `anon`·`authenticated` 권한 회수
- 서버용 `service_role`에만 `select`, `insert`, `delete`와 시퀀스 권한 부여
- `reset_restaurant_demo_data()` 함수: 하나의 트랜잭션으로 원본 3건과 다음 ID를 복원

DB 열은 snake_case(`price_range`, `recommended_menu`)이고, API 응답은 `Restaurant.fromDatabase()`가 camelCase(`priceRange`, `recommendedMenu`)로 변환합니다.

## 실행 방법

### 1. Supabase 준비

1. Supabase 프로젝트를 만들고 Data API를 활성화합니다.
2. SQL Editor에서 `supabase/schema.sql`, 이어서 `supabase/seed.sql`을 실행합니다.
3. Project URL과 서버용 Secret key(`sb_secret_...`)를 확인합니다. Publishable key는 사용하지 않습니다.

### 2. 환경변수

```bash
cp -n .env.example .env
```

`.env`에 본인 값을 입력합니다. 이 파일은 Git에 올리지 않습니다.

| Key | 설명 |
|---|---|
| `PORT` | 로컬에서는 3000 |
| `NODE_ENV` | 로컬에서는 development |
| `SUPABASE_URL` | 프로젝트 기본 URL (`/rest/v1`을 붙이지 않음) |
| `SUPABASE_SECRET_KEY` | 서버용 Secret key. React의 `VITE_*`에 넣지 않음 |

### 3. 설치와 실행

```bash
npm install --include=dev
npm run db:check      # 실제 Supabase 연결 확인
npm run dev           # 개발 서버
```

빌드한 서버는 다음과 같이 실행합니다.

```bash
npm run build
npm start
```

## 스크립트

| 명령 | 작업 |
|---|---|
| `npm run typecheck` | 서버·테스트·스크립트 타입 확인 |
| `npm test` | Jest 28건과 PGlite SQL 6건 실행 |
| `npm run build` | TypeScript 컴파일 후 원본 JSON을 `dist`로 복사 |
| `npm run db:check` | 실제 Supabase를 최대 한 행 읽어 연결 확인 |
| `npm run dev` | `tsx watch`로 소스 실행 |
| `npm start` | 빌드한 `dist/server.js` 실행 |

`npm test`는 Supabase 응답을 흉내 낸 테스트용 클라이언트와 로컬 PGlite를 쓰므로 실제 DB를 수정하지 않습니다.

## 배포

- **서버:** Render Web Service
  - Build Command: `npm ci --include=dev && npm run build`
  - Start Command: `npm start`
  - Health Check Path: `/health`
  - 환경변수: `NODE_ENV=production`, `NODE_VERSION=24.22.1`, `SUPABASE_URL`, `SUPABASE_SECRET_KEY`
- **클라이언트:** Vercel. `VITE_API_BASE_URL`에 Render의 기본 주소를 설정합니다 (`/api/restaurants`는 붙이지 않음).

## 영구 저장 확인

1. `POST /api/restaurants`로 맛집을 등록하고 응답의 `data.id`를 기록합니다.
2. 서버 프로세스를 Ctrl+C로 완전히 종료한 뒤 다시 실행합니다.
3. `GET /api/restaurants/:id`와 목록을 다시 조회해 같은 ID와 필드가 남아 있는지 확인합니다.

검증 행을 지우려고 `reset-demo`를 호출하지 마세요. 추가한 행이 모두 삭제됩니다.
